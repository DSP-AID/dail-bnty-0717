# Big Data Bowl 2027 — Combine Tracking Data Audit

Quantified pre-build audit of the NFL Big Data Bowl 2027 release (Kaggle
[`nfl-big-data-bowl-2027`](https://www.kaggle.com/competitions/nfl-big-data-bowl-2027/data)):
**510 rookies, 6,310 Combine drill events, 9 CSVs (~2.3 GB)**. Every number in the
[audit report](AUDIT_REPORT.md) is machine-generated by
[`scripts/audit.py`](scripts/audit.py) and self-asserts on rerun.

## Quickstart

```bash
pip install -r requirements.txt
python scripts/audit.py --selftest     # audits data/ shipped in this repo, asserts 57 headline numbers
python -m pytest tests/ -q             # same checks via pytest (or: python tests/test_audit.py)
```

Expected output on a clean machine (no Kaggle token needed):

```
[selftest] 59/74 checks passed, 15 FULL-scope checks skipped (full game CSVs absent from data/)
```

To verify the remaining 15 checks, download the four big game CSVs from the
competition (login required), drop them into `data/`, and rerun — `checksums.json`
pins all nine official files by sha256/byte size so you know you have the same bytes:

```bash
python scripts/audit.py --selftest   # -> [selftest] 74/74 checks passed, 0 FULL-scope checks executed
```

## Headline findings (details + reproduction in [AUDIT_REPORT.md](AUDIT_REPORT.md))

| ID | Finding | Quantified |
|---|---|---|
| F1 | Duplicate drill labels: same `(nfl_id, draft_year, drill_type, attempt)` recorded under multiple `event_id`s (separate sessions 0.08–1.42 h apart) | **514 keys / 223,772 rows (48.3 % of the tracking file)**; up to 13 events per key |
| F2 | `dis`/`s` are not reconcilable with `x`/`y` — they are independent sensor estimates, not step math | `dis` ≠ hypot(Δx,Δy) by >0.05 yd on **426,473 / 456,328** consecutive frames (median error 0.213 yd); a 40-yd dash sums to 36.74 yd of `dis` vs 40.43 yd x-span |
| F3 | `event_id` format split: 2023 uses Mongo-ObjectId ids (`6414…-2023`), 2024/25 use `YYYYMMDDHHMMSS_epochms_seq` | **136,097 rows / 1,966 events (29.4 %)** break naive `event_id[:8]` date parsing |
| F4 | Official stopwatch times with **no** sensor clip (and vice versa) | forty 6/424, three-cone 30/180, shuttle 41/201 missing tracking; 10+10 tracked without official time |
| F5 | Attempt-number holes (earlier attempts never captured) | **153** groups start above attempt 1; **84** more have interior holes |
| F6 | `y` violates the documented `[0, 53.3]` field bounds — combine coords use a different origin (forty corridor is y ∈ [−2.25, 2.70]) | **50,360 rows (10.9 %)**; x violations: 0 |
| F7 | Ball tracked only in WR/TE catch drills; `(event_id, time)` is not a unique key once BALL+PLAYER share slots | ball in **551 / 6,310** events (18/56 drill names); 32,095 dual-entity slots; grain is `(event_id, entity_type, time)` |
| F8 | `player_play.csv`: 12,822 embedded newlines in `play_description` (`wc -l` overcounts by that many) + official column typo `visitor_team_win_probility_added` | parsed 314,197 vs raw lines 327,019 |
| F9 | Truncated clips | 4 events ≤ 20 rows (shortest 0.9 s for a three-cone) |
| F10 | Missing values are opt-out-shaped, not corruption: `combine_results` nulls (three-cone 330, shuttle 309, bench 318, forty 86…), players 127 UDFAs; tracking file itself has **0** null cells | see §2 of the report |

Verified clean: no duplicate rows/frames anywhere, no orphan foreign keys, intra-event
frame gaps = 0 (perfect 10 Hz), referential integrity across all 510-id id sets.
